## 画布：Agent 执行审计、媒体幂等与执行层拆分

- Agent 工具结果新增 actionId、风险等级、开始时间和耗时审计信息；工具异常统一区分普通执行失败与用户停止产生的 cancelled 错误码。
- 媒体生成节点记录 agentRequestId；同一 Agent 动作重试时复用已有节点和任务，已失败节点不会伪装成成功，需使用新的请求重新提交。
- 画布工具风险集中到 canvas-agent-registry，分为读取 / 普通写入 / 破坏性 / 高成本四档，并提供「是否需要确认」「是否清除自动标题待定」等语义；执行器和运行时不再各自维护工具名白名单。
- Agent 新建节点的落点计算抽成纯函数 canvas-agent-layout（优先放在直接来源右侧，否则按 3 列网格避让），避免新节点压住已有节点。
- 只读查询抽成 canvas-agent-read-tools：节点关键词分页查询、直接上下游、媒体节点判定；查询行为与返回字段保持不变。
- 媒体参数与节点元数据构造抽成 canvas-agent-media：模型配置、视频时长与声音能力、TTS 音色分别落到 metadata，校验顺序与错误码保持不变。
- 写操作结果计算抽成 canvas-agent-write-tools：创建/更新文本节点、更新标题、创建连线、4 列排列（分组随组头位移）都先算好新节点与新连线，再由 Hook 一次性提交；主剧本固定尺寸常量同步迁移。
- 批次原子性：运行时把一批工具动作视为一个批次，开始前由执行器快照节点/连线/选中，批次结束后回传汇总（总数 / 成功 / 失败 / 是否回滚）；当整批都是结构写入且存在失败时，整体回滚到执行前状态，并在工具结果与协议消息里标注 rolledBack。
- 批次汇总会作为一条附注回传模型（仅失败时），避免模型误判"部分成功"；删除节点、媒体提交、主剧本改名不在可回滚范围内，失败时保留已完成部分并提示保留策略。
- 回滚同时还原 agentState（阶段、已批准节点、参考节点），避免"结构已回滚但状态仍记录失败批次内容"的不一致。
- 批次脚注下方展示本批创建/触及的节点（最多 20 个，标题为胶囊按钮），点击可定位到画布节点；节点已删除时自动不显示。
- 助手消息新增批次统计脚注：一次执行超过 1 个动作或存在失败时，在回复下方显示「本批 N 个操作 · 成功 X · 失败 Y · 已回滚」，单动作成功不显示；一轮内多个批次会累加统计，任一批次回滚即标记「已回滚」。
- 媒体确认卡显示预估算力点：自动生成前的确认文案追加「预计 N 算力点」（复用工作台 requestCreditCost；本地渠道为 0 时不显示），删除类确认不受影响。
- Agent 设置新增「提交生成前确认」开关（CanvasAgentConfig.confirmMediaGeneration，默认开启）：开启自动生成时可选择媒体任务直接提交、不再逐次弹确认；删除节点/连线的确认不受该开关影响。
- 确认请求串行排队：媒体批次是并行执行的，确认卡同一时刻只能展示一个，现在多个待确认动作会依次弹出（前一个取消或失败不会阻塞后一个），不再出现后一个覆盖前一个、前者被静默取消的问题。
- 确认改为注册表驱动：删除节点、删除连线一律先确认（文案含节点标题 / 连线两端）；自动提交生成时，图片、图片编辑、视频、音频会先显示数量、尺寸、时长、音色与提示词摘要再提交；仅创建媒体节点（未开启自动生成）不打断。取消返回 action_cancelled（删除节点仍为 delete_cancelled），画布不产生变更。
- 助手面板新增 connections 属性，用于把连线两端标题展示在确认卡里。
- 上下文裁剪：只有选中节点、已确认节点、正式参考、直接上下游和 loading/error 节点会注入正文与提示词；其余节点只保留 id / 类型 / 标题 / 状态 / 分组，媒体 URL 也不再下发，需要时由 get_node、query_canvas_nodes 读取，降低长画布首轮 token。
- 面板拆分：会话读写抽到 use-assistant-session-write；单轮执行（abort 接管、图片引用补全、模型/Codex 调用、会话回写、停止与错误状态）抽到 canvas-assistant-turn；请求配置组装、JSON 回退键、Skill 可用性校验抽到 canvas-agent-request。面板拆分后 965 行；后续新增确认开关与批次脚注后为 981 行（拆分前基线 1030 行），行为与提示文案不变。
- 检查点收紧：长期检查点上限从 16000 降到 6000 token，提示词明确禁止复述剧本、分镜、提示词与工具输出原文，只保留目标、约束、决定与未决事项；长会话压缩后注入体积更小。
- 会话恢复校正：syncAssistantReferences 会用真实画布过滤 agentState 里已删除的 approvedNodeIds / referenceNodeIds（自动去重），并清理指向已不存在节点任务的 pendingTaskIds；completedTaskIds 作为历史保留，阶段与方案不变。
- 用户停止执行时不回滚已完成的结构变更，仅清空批次快照，与"停止后已创建内容保留"的既有文案一致。
- 已知限制：回滚通过重新写入节点/连线实现，撤销栈会多出一条记录。
- Codex 模式每个工具调用即一个批次，同样会触发批次快照与判定；发生回滚时面板顶部弹出「本批操作未完成，已回滚本次画布结构变更」提示。
- use-canvas-agent-executor 从 555 行收敛到 422 行，只保留工具分发、画布状态提交、批次快照与删除/分词这类必须走现有画布链路的动作；新增 70 条单测（运行时 11、注册表 5、布局 5、只读 4、媒体 6、写操作 9、确认文案 8、上下文 4、会话校正 3、确认队列 2、请求配置 5、批次展示 5、单轮执行 3）；运行时新增模型请求注入点（requestTurn，仅测试使用）用于集成测试，覆盖失败回滚、媒体批次不回滚、agentState 还原三条路径。已验证：`bun run typecheck` 0 错误、改动目录 ESLint 0 警告、`bun run lint`（全仓）0 警告、`bun test` 59 个文件 323 条全部通过。运行时另外覆盖了 JSON 回退切换、非法参数重试、未授权整理动作拦截和 12 步安全上限。CHANGELOG Unreleased 已补版本级归纳。
- 现有工具名称、面板交互和媒体生成入口保持不变。

## AI 渠道出网代理

- AI 渠道请求的 HTTP 客户端优先使用 `HTTPS_PROXY` / `HTTP_PROXY`，Windows 下没有环境变量时自动读取系统代理（WinINET，支持 `127.0.0.1:7890` 和 `http=;https=;socks=` 两种写法），启动时打印 `outbound proxy: env|system|none`，连接失败日志也会带上代理来源。

## 开发服务器切换到 Turbopack

- 排查发现原来的 `next dev --webpack` 长时间运行后内存会累积到 14 GB 并失去响应，日志里还反复出现 `Fast Refresh had to perform a full reload`。
- 实测对比（同一台机器、同一批路由）：webpack 启动约 5.4 s、路由按需编译 5–8 s、11 条路由后常驻约 5.9 GB；Turbopack 启动约 0.4 s、路由 1.5–3.4 s（含固定等待）、11 条路由 + 画布详情页后常驻约 2.1 GB，且不再出现整页重载告警。
- `dev` 脚本改为 `next dev --turbopack`，保留 `dev:webpack` 作为回退；后台 ProTable、配置弹窗、工作流抽屉、404、画布详情页均已在 Turbopack 下验证通过。
- CI 增加 `bun run typecheck`（`next.config.ts` 里 `typescript.ignoreBuildErrors: true`，构建本身不会拦住类型错误）。
- 需验证：日常 HMR 是否正常（改组件后局部刷新、改 store/service 后按预期整页刷新）、生产构建与开发下的交互是否一致；如遇端口被旧进程占用，先确认 3000 端口的占用进程再启动。
